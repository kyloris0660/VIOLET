# 生产 Pixiv A2 实施方案

项目所有者已明确要求全量执行23号任务。PR #151已接受并合并，PR #152按39号负责人裁决接受并合并至`2b742ca3e49d4b7d361300e98e0b2d9c1a0eb63d`，日常入口已对齐此main。本轮从该基线建立一个A2分支和一个正常PR，不合并、不推main、不触发额外reviewer、不进入A3。

## 三个连续步骤

1. **范围、兼容与累计所有权。** 数据库只读快照固定T0和Media/work/page映射；优先可信来源解决先验冲突，保留未解决归宿。盘点真实metadata、规范化输入和持久裁决缓存。修正artist带页面context的适配问题，保留作者稳定ID和角色/作品上下文。为正式固定scope扩展既有产品run投影，明确A1到全量的事务替换、累计更新与owned rollback。
2. **获取与完整裁决。** 复用既有metadata队列、metadata-only gallery-dl执行器及work checkpoint；缓存与保存payload先复用。请求间隔至少2秒、同一work最多3次尝试并跨续跑累计。复用resolver候选、确定性关系与兼容judgments，通过明确生产入口接入付费裁决。所有新调用、失败、重试共享USD 10上限，按实际模型单价、usage和保守预留控制。
3. **全量生产落地与验收。** 针对实际写入取得备份和独立恢复证据，在副本验证A1过渡、重复执行、输入变化、独立支持、rollback和分批等价，再通过既有profile/controller部署候选并落地有效全量。验证普通搜索、AND/负向/建议/来源chip、真实图片详情和正常launcher；记录全量性能、预算与全部未完成归宿。

## 实现选择和迁移边界

复用`SourceMetadataRecord`、既有队列和`SourceConceptProductRun`/binding/事务模型。先确认现有JSON范围和projection数据能否支持原子累计替换；只有必要时增加字段，迁移方案在执行前写入本方案并先在恢复副本验证。不得放大旧1%–5% canary百分比或通过轮换active run伪造全量。跨批次共享逻辑输入空间，不能建立永久分裂的概念孤岛。

缓存按角色、context、模型、提示词和策略身份判断兼容；不把历史通用ProviderCache计数当作裁决缓存。原始事实不重写，作者context修复在生产适配层表达并保存版本。

生产裁决先处理作品异名，再将同一resolver实际允许合并的作品组件用于角色上下文，最后裁决角色候选。作品共现标签不作为彼此的所属作品；显式作品/括号上下文和cannot-link仍生效。推导上下文保持原有证据强度，作品身份不会自动授予角色身份。

模型给出的work_context必须能在同一实际作品中找到明确的work角色标签，不能仅因“制服”“兔女郎”等字符串出现在来源中就把它当作所属作品。无法证明的模型上下文保留原值与拒绝原因，不进入硬上下文；来源括号和已接受词汇的上下文证据继续保留。完整原始角色响应仍可复用，不重新调用模型。

真实响应曾只复述局部确定性提示而遗漏其他名称。角色补全只针对冻结上下文中仍为unknown/person的名称，保留原问题、响应和成功缓存；补全请求明确列出剩余原始标签，以完整真实标签组作为上下文，仍经F7a验证。每个聚合最多完成一次该补全，未知项保留，不循环改写问题追求肯定答案。正常上下文批量可在1–10组内调节，6000输出token和USD10共享上限不变。

尚未处理的聚合直接使用该明确列出目标名称的上下文请求，避免先运行已发现会遗漏名称的旧问题。已完成的旧上下文按原身份读取，明确名称直接保留，补全只覆盖剩余unknown/person。小批预检的成功缓存用于同一冻结输入的后续全量续跑。

剩余名称补全可使用最多两个文本worker，每个独立provider实例持有自己的usage，跨worker共用同一持久预算和认证/限流/连续传输错误暂停门禁。成功单元只有一个writer，先恢复原始付费响应再分配工作；不改变模型、提示词、token上限或Pixiv获取并发。实际启用前先做隔离预算竞争、部分失败和缓存续跑验证。

配对裁决的作品与其他名称两步共享同一调用暂停状态；401/403/429立即停止后续新请求，连续三次传输失败也暂停。暂停后仍读取成功缓存，未发出的请求不预留或计费。普通解析失败保留原始响应并按既定单项尝试上限处理，不扩大到另一个provider。

本次未增加数据库schema。正式范围、水位、固定Media/work/page和投影版本存入既有run JSON。生产支持使用固定`production_pixiv`键空间，所有批次和代际共用；语义仍由既有resolver决定，支持归属不会通过全局upsert转移其他消费者的行。旧投影通过合法owned rollback退出，新投影在同一事务提交后可见；后续出现未知独立引用时，原guard仍拒绝破坏性撤回。

只有固定映射中通过实际来源provenance验证的完整记录进入概念输入。缺失的远端页码单独记账，不影响同一作品已验证的页面；T0后新增作为尾部，不改变既定范围。全部Media、work和page归宿由同一快照命令产生。

## 运行保护

保持原生产可用，长时间获取不冻结图库。只在必要切换窗口协调本应用写入。原数据库、存储、认证和模型保留；不重跑导入/分类/WD/本地化，不修改人工标签、相册或确认Entity。A3前置债按39号裁决保留，本轮不运行advanced_full_rescan或改变导入恢复处置。
